# PURPLE RABBIT LINE — v0.07 紫うさぎの隊列スネーク (pyxel.cube版)

正式タイトルは **PURPLE RABBIT LINE** です (開発中の呼称: 3D SNAKE。
画面には出さず、識別用にだけ残しています)。

Pyxel 製の 3D スネークゲームです。プレイヤーは **紫うさぎの隊列**。
餌は **リス** と **オレンジの子** の 3D モデルで、画面に同時に
1 体ずつ存在します。

## 遊び方

```bash
pip install pyxel        # または同梱の venv を使う
python main.py
```

| キー | 動作 |
|---|---|
| ENTER / SPACE | スタート (ゲームオーバー画面では ENTER のみ有効) |
| ← → または A/D | 旋回 |
| SPACE (プレイ中) | ジャンプ |
| ↑ / W | ブースト |
| ↓ / S | ブレーキ |
| M | サウンド ON/OFF |

操作はカーソルキーと WASD の両方に対応しています。ゲームパッド
(Web 版の仮想ゲームパッドを含む) にも対応し、十字キーで旋回・
ブースト・ブレーキ、A ボタンでジャンプと決定、START ボタンで
決定ができます (ミュート切替のみ M キー)。モデルの
縁取りは常時 ON (切り替えキーなし) です。

## ルール

- 移動はグリッド単位ではなく**連続**。先頭が進み、後続は先頭が
  通った軌跡を一定間隔で辿って 1 列に歩きます (歩行アニメーション付き)。
- **スタートは 1 体だけ**。ステージは 25×25 と少し小さめです。
- どちらの餌を食べても隊列が **1 体** 伸びます。食べた方だけが
  別の場所に再配置され、もう一方は残ります。食べた瞬間には
  パーティクルと「+1」の演出が出ます。
- **SPACE でジャンプ**。後続は「先頭がその地点で跳んでいた高さ」を
  距離遅れでトレースするので、ジャンプが波のように隊列を伝わります。
- 先頭が十分高く跳んでいる間は自分の隊列に衝突しません。
  **隊列を飛び越してゲームオーバーを回避**できます。
- 一方、**高く跳んでいる間 (高さ 0.5 超) は餌を食べられません**。
  ジャンプで A/C を飛び越すと取り逃がしてスコアが伸びません
  (餌はその場に残るので、地面で戻れば食べ直せます)。
- **壁はジャンプでは越えられません**。空中でも激突すればゲームオーバー。
- 地面にいる時に自分の隊列に触れてもゲームオーバー。
- **ペンギン (障害物) が、開始時に 1 体、以後 10 秒ごとに
  1 体ずつ出現**します。
  頭が触れるとミスでゲームオーバー。**隊列と同じくジャンプで
  飛び越してかわせます**。タイミングがシビアにならないよう、
  ペンギン用の回避ラインは隊列より低め (高さ 0.5) に設定してあり、
  実測では正面 5.5 先のペンギンに対してジャンプ開始の猶予は
  約 0.7 秒 (21 フレーム) あります。出現位置は頭・隊列・餌から
  離れた空き場所が選ばれ、ミニマップでは黒丸で表示されます。
- 状態遷移は **タイトル → 開始待機 → ゲーム中 → ゲームオーバー →
  タイトル**。スタートすると、まず初期配置が見える状態で 1 秒
  待機してから動き始めます (タイトルが消えた瞬間に目の前の
  ペンギンへ激突するのを防ぐため)。
  ゲームオーバー画面で ENTER を押すとタイトルへ戻ります
  (直後 1 秒はキーを受け付けず、SPACE では戻りません。ジャンプの
  連打で画面が一瞬で消えるのを防ぐためです)
  (直接リスタートはしません)。

## サウンド

- BGM: 3 チャンネル (メロディ / ベース / リズム) のループ、
  タイトル画面から再生。SE は専用チャンネルで BGM を止めません。
- 効果音: 取得 / スタート / ゲームオーバー / 旋回開始 / ジャンプ。
- M キーでミュート切替 (状態は左上に表示)。

## 技術メモ

- 3D は Pyxel 3.0 のネイティブ3Dエンジン `pyxel.cube` を使用。
  深度バッファがあるため、面の描画順ソート (画家アルゴリズム) は
  不要で、内側のパーツが透けて見えることもありません。
  (旧版の自前ソフトウェア描画で必要だった壁の12分割や顔パッチの
  手前補正といった対策は、Cube版では不要になりました)
- キャラクター4体は GLB (assets/*.glb) を読み込んで描画します。
  GLB はパーツ定義から直接生成したもので, パーツ名とグループ構成を
  保持しています。うさぎの歩行は GLB 内の関節ノード
  (leg_l / arm_r / ear_l など) を回して再現します。
- 同じパーツ定義から Blockbench 用ファイル (assets/*.bbmodel,
  Generic 形式・キューブ要素・パレットテクスチャ方式) も生成して
  あり, モデルの編集はそちらで行えます。編集したら
  `python tools/gen_models.py` で .bbmodel / .glb を再生成してください。
- 地面は静的ジオメトリを Primitive にマージして描画します。
- フィールドは **正 12 角形** で、**電車の車両** が
  1 辺に 1 両ずつループ状に囲むデザインです (銀の車体、黒い窓、
  ドア自体が緑の両開きドア、屋根と空調、線路盤)。
  車両の厚みは実寸比 (幅 2.95m / 長さ 19.5m) にしています。
  ドアと窓の配置も実寸比 (車体長 19.5m 換算) で、1 両にドア
  4 か所 (幅 1.3m、中心は車端から 2.25 / 7.25 / 12.25 /
  17.25m)、ドアの間に窓、車両端とドアの間に狭い窓を入れて
  います。車両同士の継ぎ目は描きません。車両も色ごとに
  Primitive へマージして描画します。
- 地面は緑と白のチェッカーです。
- 当たり判定は 12 角形の境界で、従来の壁と同じくジャンプでは
  越えられません。
- モデルの縁取りは Pyxel 3.0.4 で追加された `Node.outline` を使用
  (キャラクターのアクターに黒の縁取り)。常時 ON です。
  そのため Pyxel は 3.0.4 以上が必要です。
- HUD には SCORE と BEST のみ表示します。隊列の長さ (LENGTH) と
  A/C ごとの取得数は表示しません (ロジック内部では保持しています)。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `main.py` | Pyxel アプリ本体 (入力・状態遷移・HUD・サウンド) |
| `index.html` | GitHub Pages 用の紹介・プレイ用ページ (ゲーム本体を埋め込み) |
| `snake_logic.py` | ゲームロジック (Pyxel 非依存、軌跡・ジャンプ履歴・衝突判定) |
| `characters.py` | リス / オレンジの子のモデル定義 |
| `rabbit_model.py` | 紫うさぎのモデル (歩行デモから流用) |
| `models.py` | 直方体パーツ・面生成・パレットの共通基盤 |
| `cube_render.py` | pyxel.cube のシーン・追従カメラ・GLBアクター制御・食べ演出の粒配置 |
| `tests/test_snake.py` | ロジックの自動テスト 17 件 |
| `tools/gen_models.py` | パーツ定義から assets の .bbmodel / .glb を生成 |
| `tools/preview.py` | 実機画面を撮影して previews/ に PNG を生成 (Xvfb + ffmpeg が必要) |
| `tools/gen_obj.py` | モデルを assets/ に OBJ/MTL で書き出す |
| `assets/` | キャラ4体の .bbmodel と .glb (a_squirrel / b_rabbit / c_kid / d_penguin) と OBJ/MTL |
| `previews/` | プレビュー画像 (版ごとの履歴を含む) |

## 検証

- `python tests/test_snake.py` — ロジックテスト 17 件 (連続移動、軌跡追従、
  A/C 同時配置、成長、壁衝突、ジャンプ中も壁は激突、自己衝突、
  ジャンプ物理と波のトレース、隊列の飛び越し回避、餌の飛び越し取り逃がし、ペンギンの
  出現間隔・配置ルール・衝突・飛び越し可能・低すぎる跳躍はミス)
- Pyxel 実機ハーネス (Xvfb): 状態遷移 タイトル→プレイ→
  ゲームオーバー (ペンギン接触) →タイトル→プレイ を実入力で確認済み。
  ジャンプ、取得、BGM/SE の発火も記録して確認済み
- フレーム時間 (VM実測, 隊列15体): 中央値 約5.6ms / フレーム
  (30fps の予算 33ms に対して十分に余裕あり)
